# Contributing to Draftdown

Draftdown welcomes contributions from the community. You do not have to be an experienced developer to help out—reporting bugs, suggesting enhancements, improving documentation, and submitting pull requests are all valuable ways to contribute.

> [!TIP]
> Please view our [Code of Conduct](./CODE_OF_CONDUCT.md) to understand how we expect contributors and maintainers to interact.

## Report Issues & Request Features

If you find a bug or have an idea for an enhancement or new feature, please open an issue on the [GitHub issue tracker](https://github.com/davidyshen/MDWriter/issues) using the appropriate issue template.

> [!IMPORTANT]
> Keep your GitHub notifications active after opening an issue or pull request so you can respond to follow-up questions.

## Code Contributions

We welcome pull requests that fix bugs, improve behaviour, or implement new features. You can find setup instructions and the project architecture overview in [README.md](./README.md).

Before opening a pull request:
1. Ensure static analysis passes cleanly (`flutter analyze`).
2. Ensure all existing and new tests pass (`flutter test`).
3. Use British English spelling in documentation and user-facing copy.
4. Fill in the [pull request template](./.github/PULL_REQUEST_TEMPLATE.md) when submitting your PR.

## AI Usage Policy

Draftdown does not prohibit the use of generative AI / LLMs as coding aids, provided you:
* Disclose AI usage in the pull request description.
* Review, understand, and take full responsibility for all code and text you submit.
* Never list AI tools or chatbots as commit co-authors.
* Write issue descriptions, PR descriptions, and comments yourself rather than submitting unedited AI-generated prose.
